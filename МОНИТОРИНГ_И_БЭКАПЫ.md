# Мониторинг и резервное копирование DIGroup

## Мониторинг

### Компоненты

Система мониторинга включает:
- **Prometheus** - сбор метрик
- **Grafana** - визуализация
- **Node Exporter** - метрики системы

### Запуск

Мониторинг запускается автоматически с основным приложением:

```bash
./start.sh
```

Или вручную:

```bash
docker-compose up -d
```

### Доступ к интерфейсам

**Grafana:**
- URL: http://localhost:3000
- Логин: admin
- Пароль: указан в .env (GRAFANA_PASSWORD) или admin по умолчанию

**Prometheus:**
- URL: http://localhost:9090
- Доступ без аутентификации (только localhost)

**Node Exporter:**
- URL: http://localhost:9100/metrics
- Метрики системы в формате Prometheus

### Настройка Grafana

При первом входе:

1. Откройте http://localhost:3000
2. Войдите (admin/admin или ваш пароль из .env)
3. Измените пароль (рекомендуется)
4. Перейдите в Dashboards → DIGroup System Monitoring

### Доступные метрики

**Система:**
- CPU Usage - использование процессора
- Memory Usage - использование памяти
- Disk Usage - использование диска
- Network I/O - сетевая активность

**Приложение:**
- Container Status - статус контейнера
- Health Check - результаты проверок здоровья
- Uptime - время работы

### Настройка алертов

Prometheus настроен на отправку алертов при:
- CPU > 80% более 5 минут
- Memory > 90%
- Disk > 85%
- Container down более 1 минуты

Для получения уведомлений настройте Alertmanager (опционально).

## Резервное копирование

### Автоматические бэкапы

Настройка ежедневного бэкапа (по умолчанию в 02:00):

```bash
./setup-backup.sh
```

Или с указанием времени:

```bash
./setup-backup.sh 03:30  # бэкап в 3:30 ночи
```

### Ручной бэкап

Создание бэкапа вручную:

```bash
./backup.sh
```

### Что сохраняется

Автоматически сохраняются:
- `workspace/` - все документы и данные пользователей
- `data/` - служебные данные приложения
- `.env` - конфигурация

### Хранение бэкапов

**Локация:** `./backups/`

**Формат:** 
- `workspace_YYYYMMDD_HHMMSS.tar.gz`
- `data_YYYYMMDD_HHMMSS.tar.gz`
- `.env_YYYYMMDD_HHMMSS`

**Ретенция:** 30 дней (старые автоматически удаляются)

### Восстановление из бэкапа

```bash
# Остановите приложение
docker-compose down

# Восстановите workspace
tar -xzf backups/workspace_YYYYMMDD_HHMMSS.tar.gz

# Восстановите data (если нужно)
tar -xzf backups/data_YYYYMMDD_HHMMSS.tar.gz

# Запустите приложение
docker-compose up -d
```

### Просмотр логов бэкапов

```bash
# Логи ручных бэкапов
tail -f logs/backup.log

# Логи автоматических (cron)
tail -f logs/backup-cron.log
```

### Проверка cron задачи

```bash
# Просмотр всех задач
crontab -l

# Удаление автобэкапов
crontab -l | grep -v backup.sh | crontab -
```

## Локальное хранение данных

Все данные хранятся локально на сервере:

**Основные данные:**
- `./workspace/` - документы пользователей
- `./data/` - служебные данные
- `./backups/` - резервные копии

**Данные Docker:**
- `prometheus_data` - метрики Prometheus
- `grafana_data` - конфигурация Grafana

**Логи:**
- `./logs/` - логи приложения и бэкапов
- Docker логи: `docker-compose logs`

### Проверка использования места

```bash
# Основные директории
du -sh workspace data backups logs

# Все вместе
du -sh .

# Docker volumes
docker system df -v
```

## Рекомендации

### Для production

1. **Увеличьте retention бэкапов до 60-90 дней**
   
   Отредактируйте `backup.sh`:
   ```bash
   RETENTION_DAYS=90
   ```

2. **Копируйте бэкапы на удаленный сервер**
   
   Добавьте в конец `backup.sh`:
   ```bash
   # Копирование на удаленный сервер
   rsync -avz backups/ user@backup-server:/backups/digroup/
   ```

3. **Мониторьте размер бэкапов**
   
   Настройте алерт в Grafana на размер директории backups

4. **Тестируйте восстановление**
   
   Раз в месяц тестируйте процесс восстановления из бэкапа

### Безопасность

1. Ограничьте доступ к бэкапам:
   ```bash
   chmod 700 backups/
   ```

2. Шифруйте бэкапы (опционально):
   ```bash
   gpg --encrypt --recipient your@email.com backup.tar.gz
   ```

3. Храните бэкапы на отдельном диске/сервере

## Решение проблем

### Бэкап не создается

Проверьте:
```bash
# Права на директорию
ls -la backups/

# Доступное место
df -h

# Логи
cat logs/backup.log
```

### Cron не запускается

```bash
# Проверьте cron службу
sudo systemctl status cron  # Ubuntu/Debian
sudo systemctl status crond # CentOS/RHEL

# Проверьте права на скрипт
ls -la backup.sh
```

### Grafana не показывает данные

```bash
# Проверьте Prometheus
curl http://localhost:9090/api/v1/targets

# Проверьте datasource в Grafana
# Settings → Data Sources → Prometheus
```
