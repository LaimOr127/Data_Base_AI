## 🔐 Формат логинов и паролей

### Логин:
- Формируется из инициалов: **Первая буква фамилии + Первая буква имени**
- Пример: "Шулаков Андрей Дмитриевич" → `sha`

### Пароль:
- Формируется из инициалов + "123": **Инициалы + "123"**
- Пример: `sha123`

### Гостевой доступ:
- **Логин:** `guest`
- **Пароль:** `guest123`
- **Роль:** Visitor (только чтение)

## 🔧 Интеграция с DIGroup

DIGroup использует систему аутентификации через `AccessAuthCode`. Для многопользовательского доступа есть несколько вариантов:

### Вариант 1: Использование Publish Service (рекомендуется)

Publish Service позволяет настроить базовую аутентификацию для доступа к опубликованному контенту.

**Настройка через конфигурацию:**

1. Откройте `~/DIGroup-workspace/conf/conf.json`
2. Найдите секцию `publish`
3. Добавьте пользователей:

```json
{
  "publish": {
    "enable": true,
    "auth": {
      "enable": true,
      "accounts": [
        {
          "username": "sha",
          "password": "sha123"
        },
        {
          "username": "fk",
          "password": "fk123"
        }
        // ... добавьте всех пользователей
      ]
    }
  }
}
```

### Вариант 2: Использование AccessAuthCode для каждого пользователя

Можно создать отдельные AccessAuthCode для каждого пользователя, но это менее удобно.

### Вариант 3: Кастомная система аутентификации (требует разработки)

Можно создать собственную систему аутентификации через API, но это требует изменений в коде kernel.

## 🌐 Доступ для пользователей

### Для сотрудников:
1. Откройте `http://localhost:8081` (или IP сервера)
2. Введите AccessAuthCode (общий для всех)
3. Для доступа к опубликованному контенту используйте Basic Auth:
   - **Username:** их логин (например, `sha`)
   - **Password:** их пароль (например, `sha123`)

### Для гостевого доступа:
- **Логин:** `guest`
- **Пароль:** `guest123`
- **Права:** Только чтение

## 🔄 Синхронизация между устройствами

Для работы с нескольких устройств:

2. Используйте общую папку синхронизации

## ⚠️ Важно

1. **Безопасность:** Пароли простые (инициалы + 123). Для продакшена рекомендуется:
   - Изменить пароли на более сложные
   - Использовать систему смены паролей
   - Настроить HTTPS

2. **Роли:** По умолчанию все пользователи имеют роль `editor`. Можно настроить:
   - `administrator` - полный доступ
   - `editor` - редактирование
   - `reader` - только чтение
   - `visitor` - гостевой доступ

3. **Обновление БД:** При добавлении новых сотрудников:
   ```bash
   python3 siyuan/scripts/create_users_db.py
   ```
