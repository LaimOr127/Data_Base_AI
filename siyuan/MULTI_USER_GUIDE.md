# Руководство по многопользовательскому использованию DIGroup

## 📋 Краткий ответ

**Да, приложение может использоваться несколькими пользователями, но с важными ограничениями:**

1. ✅ **Многопользовательский доступ через веб-интерфейс** - поддерживается
2. ⚠️ **Один workspace = один kernel процесс** - нельзя запускать несколько экземпляров на одном workspace
3. ✅ **Система ролей существует** - есть разделение на админов, редакторов и читателей
4. ⚠️ **Производительность** - зависит от количества одновременных пользователей и размера данных

---

## 🔐 Система ролей и прав доступа

Приложение поддерживает **4 уровня доступа**:

### 1. **RoleAdministrator (Администратор)**
- Полный доступ ко всем функциям
- Может изменять настройки
- Может редактировать все документы
- Получается при использовании `AccessAuthCode` или API токена

### 2. **RoleEditor (Редактор)**
- Может создавать и редактировать документы
- Не может изменять системные настройки
- Настраивается через JWT токены

### 3. **RoleReader (Читатель)**
- Только чтение документов
- Не может редактировать
- Настраивается через JWT токены

### 4. **RoleVisitor (Анонимный посетитель)**
- Минимальные права
- Используется для публикации (publish)

---

## 🌐 Способы многопользовательского доступа

### Вариант 1: Веб-доступ через браузер (Рекомендуется)

**Как работает:**
- Kernel запускается на сервере (порт 6806)
- Пользователи подключаются через браузер по IP/домену
- Все используют один `AccessAuthCode` для доступа

**Настройка:**
```bash
# Запуск kernel с доступом из сети
./SiYuan-Kernel --workspace=/path/to/workspace --accessAuthCode=ВАШ_КОД
```

**Ограничения:**
- Все пользователи имеют одинаковые права (администратор)
- Нет разделения данных между пользователями
- Все видят и могут редактировать все документы

### Вариант 2: Publish Service (Публикация для чтения)

**Как работает:**
- Отдельный сервис на порту 6808
- Можно настроить отдельных пользователей с паролями
- Только для чтения опубликованных документов

**Настройка:**
1. Включить Publish Service в настройках
2. Добавить пользователей в `Settings → Publish → Auth Accounts`
3. Каждый пользователь получает свой логин/пароль

**Ограничения:**
- Только чтение (роль Reader)
- Только опубликованные документы
- Не подходит для совместной работы

### Вариант 3: JWT токены с разными ролями

**Как работает:**
- Используется система JWT токенов
- Можно выдавать токены с разными ролями (Editor, Reader)
- Токены передаются через заголовок `X-Auth-Token`

**Ограничения:**
- Требует программирования/настройки
- Не реализовано в стандартном UI
- Нужно создавать токены вручную

## ⚠️ Важные ограничения

### 1. Workspace Lock (Блокировка рабочего пространства)

**Проблема:**
- Один workspace может быть открыт только одним kernel процессом
- Файл `.lock` в workspace предотвращает одновременный запуск
- Если попытаться запустить второй kernel на том же workspace - получите ошибку

**Решение:**
- Используйте один kernel процесс для всех пользователей
- Доступ через веб-интерфейс (браузер)
- Или используйте разные workspace для разных пользователей

### 2. Нет встроенной системы пользователей

**Проблема:**
- Нет отдельных аккаунтов для каждого пользователя
- Все используют один `AccessAuthCode`
- Нет разделения данных между пользователями

**Решение:**
- Используйте разные workspace для разных пользователей
- Или используйте Publish Service для чтения
- Или реализуйте собственную систему авторизации через API

### 3. Производительность при множестве пользователей

**Что влияет:**
- Количество одновременных WebSocket соединений
- Размер базы данных и количество документов
- Скорость сети и сервера

**Оптимизация:**
- Приложение использует контроль конкурентности (`ControlConcurrency`)
- Чтение данных может выполняться параллельно
- Запись данных сериализуется (последовательно)

## 🚀 Рекомендуемые сценарии использования

### Сценарий 1: Команда до 10 человек, совместная работа

**Настройка:**
1. Запустите kernel на сервере с доступом из сети
2. Настройте `--accessAuthCode` (обязательно!)
3. Пользователи подключаются через браузер
4. Все работают в одном workspace

**Плюсы:**
- Простая настройка
- Все видят изменения в реальном времени
- Совместная работа над документами

**Минусы:**
- Нет разделения прав
- Все могут редактировать все
- Нет истории изменений по пользователям

### Сценарий 2: Много пользователей, только чтение

**Настройка:**
1. Включите Publish Service
2. Добавьте пользователей в настройках
3. Опубликуйте нужные документы
4. Пользователи читают через publish порт (6808)

**Плюсы:**
- Безопасность (только чтение)
- Отдельные аккаунты
- Не нагружает основной workspace

**Минусы:**
- Только чтение
- Нужно публиковать документы вручную

### Сценарий 3: Разные команды, разные workspace

**Настройка:**
1. Создайте отдельные workspace для каждой команды
2. Запустите отдельные kernel процессы для каждого workspace
3. Используйте разные порты (6806, 6807, 6808...)

**Плюсы:**
- Полная изоляция данных
- Разные настройки для разных команд
- Масштабируемость

**Минусы:**
- Больше ресурсов сервера
- Сложнее управление

## 🔧 Технические детали

### Контроль конкурентности

Приложение использует механизм `ControlConcurrency`:
- **Чтение** (get, list, search) - может выполняться параллельно
- **Запись** (create, update, delete) - выполняется последовательно
- WebSocket соединения - не блокируются

### WebSocket для real-time обновлений

- Каждый пользователь имеет свое WebSocket соединение
- Изменения одного пользователя видны другим в реальном времени
- Максимальный размер сообщения: 8MB

### Блокировка workspace

```go
// Файл: kernel/util/working.go
WorkspaceLock = flock.New(filepath.Join(WorkspaceDir, ".lock"))
```

- Файл `.lock` создается при запуске kernel
- Удаляется при корректном завершении
- Если kernel завершился некорректно - нужно удалить `.lock` вручную

## 📊 Производительность

### Рекомендации:

- **До 5 пользователей** - без проблем
- **5-20 пользователей** - нормально, зависит от нагрузки
- **20+ пользователей** - может потребоваться оптимизация

### Что влияет на производительность:

1. **Размер базы данных** - чем больше документов, тем медленнее
2. **Количество одновременных операций записи** - сериализуются
3. **Скорость диска** - SSD рекомендуется
4. **Оперативная память** - минимум 4GB, рекомендуется 8GB+

- ✅ Да, через веб-интерфейс

- ⚠️ Зависит от нагрузки и конфигурации
